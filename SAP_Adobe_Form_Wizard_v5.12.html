 SAP S/4HANA — Pre-requisites

    


      

        
1. Create a Copy of the SAP Pre-Delivered Standard Content Form

        
    
          
  1. Open the Maintain Form Templates Fiori app.
    2. 
          
  2. Go to the Pre-delivered Templates tab and search for the relevant standard content form (e.g., MM_PUR_PURCHASE_ORDER for Purchase Order).
    3. 
          
  3. Select the form and click Copy, enter a custom form name e.g., YY1_MM_PUR_PURCHASE_ORDER (YY1_ is prefix) and click Create — the system creates a copy under the Custom Templates tab.
    4. 
          
  4. Go to Custom Templates tab, open your custom form and click Download — the file downloads as a .zip. Extract it to a local folder.
    5. 
          
  5. Open the .XDP file in Form Wizard / Adobe LiveCycle Designer and make required layout changes.
    6. 
          
  6. Save the modified form as an .XDP file locally and return to Maintain Form Templates.
    7. 
          
  7. Open the copied custom content form, click Upload, and upload the updated .XDP file.
    8. 
        

      


      

        
2. Create a Copy of the SAP Pre-Delivered Standard Master Form (Optional)

        
    
          
  1. Open the Maintain Form Templates Fiori app.
    2. 
          
  2. Go to the Pre-delivered Templates tab and search for the relevant master form (e.g., SOMU_FORM_MASTER_A4).
    3. 
          
  3. Select the master form and click Copy, enter a custom form name and click Create — the system creates a copy under the Custom Templates tab.
    4. 
          
  4. Open the copied master form and click Download to get the .XDP file.
    5. 
          
  5. Open the .XDP file in Form Wizard / Adobe LiveCycle Designer and make required layout changes (e.g., logo placement, footer areas, page size).
    6. 
          
  6. Save the modified file and return to Maintain Form Templates.
    7. 
          
  7. Open the copied custom master form, click Upload, and upload the updated .XDP file.
    8. 
        

      


      

        
3. Maintain Required Logos in the "Manage Logos" App

        
    
          
  1. Open the Manage Logos Fiori app (under the Output Management catalog).
    2. 
          
  2. Click the Add ( + ) button to upload a new logo.
    3. 
          
  3. Browse and select your company logo file.
    4. 
          
  4. Enter Name & Description for the logo and click Save.
    5. 
          
  5. Confirm the upload — the logo will appear in the list and is now available for assignment to master form templates.
    6. 
        

        
 Supported file formats are SVG, PNG, JPG, BMP, GIF, TIFF. Image size should not be greater than 5 MB. Only BMP files with 1, 4, 8 or 24 bit color depths are supported. For SVG limitations, see note 2551542.

      


      

        
4. Maintain Required Sender / Footer Address in the "Manage Texts" App

        
    
          
  1. Open the Manage Texts Fiori app.
    2. 
          
  2. Click the Add ( + ) button to create a new text entry.
    3. 
          
  3. Enter Name, Description and select the text type (e.g., Sender Address or Footer).
    4. 
          
  4. Enter the required text Content (company name, address, disclaimer, etc.).
    5. 
          
  5. Optionally, click Add Language to provide translations for additional languages.
    6. 
          
  6. Save the text entry — it is now available for assignment in master form configuration rules.
    7. 
        

      


      

        
5. Complete Form Configuration in Implementation Activities

        
    
          
  1. Open the Implementation Activities app.
    2. 
          
  2. Navigate to General Settings → Extensibility → Output Management → Assign Form Templates.
    3. 
          
  3. Open the activity and click Edit and New Entries and provide relevant Application Object Type, Output Type (e.g., Purchase_Order, Billing_Document), Form Template ID (e.g., YY1_MM_PUR_PURCHASE_ORDER).
    4. 
          
  4. Click Save, create a new TR or use the existing TR as per requirement.
    5. 
          
  5. Navigate to General Settings → Extensibility → Output Management → Define Rules for Determination of Master Form Template.
    6. 
          
  6. Open activity, click Edit & New Entries and provide the custom content form name and custom master form name created in steps 1 & 2.
    7. 
          
  7. In the same entry, assign the Logo, Sender Address, and Footer texts maintained in steps 3 & 4. Optionally restrict the rule by company code, country, or other business criteria.
    8. 
          
  8. Save the configuration entry. Create a new TR or use the existing TR as per requirement.
    9. 
        

      


      

        
6. Assign the Form in the "Output Parameter Determination" App

        
    
          
  1. Open the Output Parameter Determination Fiori app.
    2. 
          
  2. In the Show Rules For section, select the relevant business object (e.g., Purchase Order, Billing Document).
    3. 
          
  3. Select the determination step Form Template and click Edit.
    4. 
          
  4. In the decision table, click the Insert New Row ( + ) button to add a new entry.
    5. 
          
  5. Enter any relevant condition columns (e.g., company code, billing type) to restrict when the custom form applies.
    6. 
          
  6. In the Form Template result column, enter your custom content form name (e.g., YY1_MY_PO_FORM).
    7. 
          
  7. Position the new row above more general entries (most specific rules first).
    8. 
          
  8. Click Check to validate, then Activate to apply the configuration.
    9.

 1. Introduction & Purpose

        
Purpose of this guide

        
This guide explains how to use the SAP Adobe Form Wizard — a browser-based, AI-powered tool that accelerates and standardises SAP S/4HANA Public Cloud output form customisation. It covers what the tool does, who it is for, how to access it, and how to complete each of the eight guided steps from initial XDP upload through to a fully documented, SAP-ready form.


        
What is the Adobe Form Wizard?

        
A structured, eight-step web application that automates the most time-consuming parts of SAP output form customisation:

        
    
          
  • Applying structural layout changes to XDP files — rename labels, hide fields, add columns
    • 
          
  • Configuring master form properties — logo, footer, sender address, watermarks
    • 
          
  • Auto-populating custom field definitions from a mapping sheet
    • 
          
  • Generating BAdI ABAP implementation code from plain-English derivation logic
    • 
          
  • Assembling a complete RICEFW specification document
    • 
          
  • Auto-populating the Processing Logic section of a Technical Specification Document (TSD)
    • 
          
  • Providing a step-by-step SAP configuration pre-requisites checklist
    • 
        

        
The wizard runs entirely in a browser — no SAP access, no Adobe LiveCycle Designer and no installation required. It connects to Claude AI for code generation, document population and XDP structural changes.


        
Why was it built?

        

          
Problem without wizardSolution with wizard

          
            
Manual XDP XML editing in Adobe LiveCycle DesignerXDP patched automatically in-browser or via Claude Code

            
ABAP hand-coded field by fieldABAP generated from plain-English derivation logic

            
RICEFW spec written from scratch per engagementRICEFW spec auto-assembled in one click

            
TSD Processing Logic written manuallyTSD auto-populated from the mapping sheet

            
Quality varies by consultant experienceConsistent output regardless of experience level

            
4–12 days per form engagement2–8 days depending on form complexity

 4. Step-by-Step Guide

        
The wizard has eight steps accessible from the navigation bar at the top. You can move between steps at any time — data entered is retained for the session.


        

          
1
Basics & Layout Changes

          

            
The starting point. Enter form identification details, upload your XDP files, upload the mapping sheet, and describe all structural layout changes.

            
    
              
  • Select the Business domain (Sales, Procurement, Finance…) and Form type — the wizard uses these to suggest the correct BAdI name and business context
    • 
              
  • Enter the Standard content form name and your Custom form name
    • 
              
  • Select Language and Paper size
    • 
              
  • Upload the Content form XDP and Master form XDP
    • 
              
  • Upload the Mapping sheet (.csv / .tsv) — this auto-fills all custom fields in Step 3
    • 
              
  • In Layout changes, list fields/sections to ADD or MODIFY (one per line) and fields to HIDE or REMOVE
    • 
              
  • Simple forms (1 page): process in a single request · Medium (2+ pages): page by page · Complex (3+ pages): in batches
    • 
            

            
Upload the mapping sheet here. The wizard parses it once and reuses it in Custom Fields (3), BAdI ABAP (4), Review (5) and TSD (7).

          

        


        

          
2
Master Form

          

            
Configure the master XDP — the layout template that wraps every page of the form.

            
    
              
  • Enter the Standard master form and your Custom master form name
    • 
              
  • Form title — keep as-is, modify position, hide or set inactive
    • 
              
  • Logos — set count (1–6) and position for portrait and landscape separately
    • 
              
  • Sender address — keep, modify position or hide
    • 
              
  • Page index — configure position for portrait and landscape
    • 
              
  • Recipient address — keep, modify or hide, and set address line captions
    • 
              
  • Watermark and folding marks — keep as-is, hide or set inactive
    • 
              
  • Footer blocks — number of active blocks (1–4), static or dynamic, apply portrait or landscape defaults
    • 
            

            
Master form changes are only needed if you are customising the master XDP layout — moving the logo, changing footer content, adjusting the sender address. If the master form is unchanged, skip this step.

          

        


        

          
3
Custom Fields

          

            
Review and manage all custom fields. If you uploaded a mapping sheet in Step 1, all rows are auto-populated.

            
    
              
  • Business context — auto-suggested from the domain and form type. Verify it matches exactly in the Custom Fields and Logic app
    • 
              
  • The mapping sheet auto-populates Technical name, Label, Data type, Binding and Derivation logic per field
    • 
              
  • Header-level and item-level custom fields are managed in separate sections
    • 
              
  • Use + Add field to add rows manually
    • 
              
  • Confirm the technical name suffix — YY1_FIELDNAME_PDH (header) / YY1_FIELDNAME_PDI (item) — and the XDP binding path
    • 
              
  • Custom fields must be created in the SAP Custom Fields and Logic app before they can be used in the form
    • 
            

            
Mapping sheet column headers should include: Technical Field Name, Label/Details, Data Type, CDS View, Logic / Comments. The wizard auto-detects these — exact capitalisation is not required.

          

        


        

          
4
BAdI ABAP Generation

          

            
Generate the complete ABAP implementation for the BAdI from the derivation logic in your custom fields.

            
    
              
  • BAdI name, interface and method are auto-suggested from the domain and form type chosen in Basics
    • 
              
  • Review the header and item BAdI parameters — Importing (read-only context) and Changing (write custom fields here)
    • 
              
  • Add any additional CDS views used in derivation logic
    • 
              
  • Click Generate — the wizard reads each field's derivation logic and identifies the pattern:
                
      
                  
    • Single CDS SELECT — "Get [field] from [CDS] where [condition]"
      • 
                  
    • Multi-field CONCATENATE — "Get and concatenate [fields] from [CDS]"
      • 
                  
    • Multi-join SELECT chains — "From joining N CDS: [1] where… [2] where…"
      • 
                
    
              
    • 
              
  • Click Copy, then paste into Custom Fields and Logic app → Create → Open Code Editor
    • 
              
  • Save & Publish, test via output preview, then transport
    • 
            

            
Derivation logic must be written in plain English matching one of the three patterns. Vague or incomplete logic produces incomplete ABAP — always review generated code before pasting into SAP.

          

        


        

          
5
Review & RICEFW Specification

          

            
Auto-generate a complete RICEFW specification from all data entered across Steps 1–4.

            
    
              
  • Click Generate review — the wizard assembles the full specification
    • 
              
  • The spec covers form identification, master form configuration, layout changes, header and item custom fields, BAdI details, derivation logic and ABAP code
    • 
              
  • Review in the text area and edit any details as needed
    • 
              
  • Click Download spec to save as a .txt file
    • 
              
  • Use it as the formal RICEFW deliverable or paste into project documentation
    • 
            

            
Generate the RICEFW spec before moving to Step 6 — it contains all field names and layout change instructions in one place, which is a useful reference when running the XDP task in Claude Code.

          

        


        

          
6
Generate & Apply XDP

          

            
Apply all structural layout changes from Step 1 to the actual XDP file. Three options are available:

            
    
              
  • Option 1 — Apply & Download: changes applied directly in the browser and the modified XDP downloads immediately. Best for simple rename or hide changes.
    • 
              
  • Option 2 — Send task to Claude: downloads a structured task file. Share it in a Claude Code session — Claude reads your XDP from disk, applies all changes (rename, hide, add, reorder) and saves the result as _CUSTOM.xdp to your Downloads folder. No XML editing or copy-paste.
    • 
              
  • Option 3 — Apply pasted response: when using claude.ai chat, paste Claude's response back into the wizard and click Apply pasted response — the wizard extracts and saves the modified XDP.
    • 
              
  • Once you have the _CUSTOM.xdp, upload it to Maintain Form Templates (ADLC) → Custom Templates → Upload
    • 
            

            
Content XDP and master XDP have separate Generate sections — apply changes to each independently. Content XDP holds the form body; master XDP holds the page layout wrapper.

            
Option 2 is recommended when the XDP is large, has many changes, or when Apply & Download does not produce the expected result. Claude Code reads directly from disk and is more reliable for complex structural changes.

          

        


        

          
7
TSD Generation

          

            
Auto-populate the Processing Logic section of your Technical Specification Document from the mapping sheet.

            
    
              
  • Upload your project TSD template (.docx / .md) — the standard template with all sections already in place
    • 
              
  • Specify the exact section heading to populate (e.g. Processing Logic) — it must match the template heading text exactly
    • 
              
  • Optionally tick Delta update to append to existing content rather than replace it
    • 
              
  • Click Generate TSD with Claude — Claude reads the mapping sheet and fills the section with all standard and custom fields, their data bindings and derivation logic
    • 
              
  • The completed TSD saves to Downloads as [TemplateName]_COMPLETED.docx
    • 
              
  • All other sections remain unchanged — complete them manually from SAP documentation
    • 
            

            
The mapping sheet must be uploaded in Step 1 before TSD generation will work properly. Without it, the wizard generates a TSD from the form details and custom fields entered manually in Step 3.

          

        


        

          
8
SAP Pre-requisites

          

            
A step-by-step checklist of the SAP Fiori app configuration required before the customised form can go live.

            
    
              
  • 1. Create a copy of the standard content form — Maintain Form Templates → Pre-delivered Templates → Copy → upload your modified XDP
    • 
              
  • 2. (Optional) Copy the standard master form (e.g. SOMU_FORM_MASTER_A4) and upload your modified master XDP
    • 
              
  • 3. Upload the company logo in the Manage Logos app — SVG, PNG, JPG, max 5 MB
    • 
              
  • 4. Create sender address and footer texts in the Manage Texts app
    • 
              
  • 5. Configure form assignment — Implementation Activities → Output Management → Assign Form Templates and Define Rules for Master Form Template
    • 
              
  • 6. Assign the form in Output Parameter Determination → select business object → Form Template determination step → add rule row → Activate
    • 
            

            
Complete these in order. Steps 1 and 2 must be done before configuration in Steps 5 and 6 — the template names created there are referenced in the configuration rules.

Enhancement — existing live form

    • 
          
  • Step 4 — BAdI ABAP: regenerate if new custom fields were added
    • 
          
  • Step 6 — Generate XDP: apply delta changes to the existing _CUSTOM.xdp
    • 
          
  • Step 7 — TSD: append new fields to the existing Processing Logic section
    • 
        

        
When enhancing an existing form, always upload the existing _CUSTOM.xdp — not the standard SAP XDP — to preserve prior customisations.

 7. Tips & Best Practices

        
Mapping sheet

        
    
          
  • Maintain the mapping sheet before starting — it drives auto-population in Custom Fields, ABAP generation and TSD
    • 
          
  • Include these columns: Technical Field Name, Label/Details, Data Type, CDS View, Logic / Comments
    • 
          
  • Write derivation logic in plain English matching one of the three ABAP patterns (SELECT, CONCATENATE, multi-join)
    • 
          
  • For standard fields, leave derivation logic blank or write "Standard binding — no derivation needed"
    • 
        

        
XDP files

        
    
          
  • Always download fresh XDP copies from SAP — do not reuse files from a previous engagement
    • 
          
  • Keep the full disk path of the XDP files — the wizard displays these for Claude Code reference
    • 
          
  • For Claude Code patching, keep XDP files in Downloads or another known local folder before sending the task
    • 
          
  • For complex forms with many layout changes, use Option 2 (Send task to Claude Code) for more reliable results
    • 
        

        
ABAP code

        
    
          
  • Always review generated ABAP before pasting into SAP — check field names, CDS view names and WHERE conditions match exactly
    • 
          
  • If a derivation pattern is not recognised, edit the logic in the Custom Fields step and regenerate
    • 
          
  • Test the BAdI implementation via output preview in SAP before transporting
    • 
        

        
Session data

        
    
          
  • All wizard data is held in browser memory for the current session — closing the tab loses it
    • 
          
  • Download the RICEFW spec (Step 5) before closing — it captures all your inputs
    • 
          
  • For long sessions, copy the generated ABAP to a text file as a backup
    • 
        

        
TSD generation

        
    
          
  • The section heading in Step 7 must match the heading in your template exactly — including capitalisation and spacing
    • 
          
  • If your TSD has multiple Processing Logic sub-sections, specify the most specific heading
    • 
          
  • Use delta/append mode when updating an existing TSD with additional fields
    • 
        

      


      
      

        
 8. Troubleshooting

        

          
IssueResolution

          
            
Mapping sheet not auto-filling fields in Step 3Ensure the file is .csv or .tsv (not .xlsx). Check column headers contain the keywords Technical, Label, Logic, CDS. Re-upload in the Basics step.

            
ABAP generation produces incomplete codeThe derivation logic does not match a recognised pattern. Rewrite in plain English: "Get [field] from [CDS] where [condition]" for SELECT, or "Get and concatenate…" for CONCATENATE.

            
Apply & Download produces no changes in the XDPField names under Layout Changes → HIDE must match XFA element names exactly (case-sensitive). Use the subform or field name as it appears in Adobe LiveCycle Designer, not the label text.

            
Claude Code task does not find the XDP fileCheck the file path shown in the wizard matches the actual disk location. Edit the path field if the file sits in a subfolder.

            
TSD section not populated correctlyVerify the section heading in Step 7 matches the template heading exactly. Confirm the mapping sheet is uploaded in Basics. Try delta/append mode instead of replace.

            
BAdI name not auto-suggestedSelect a specific form type — not just the domain — in Basics. The suggestion requires both domain and form type.

            
Generated master XDP has no changesMaster form changes are only applied if at least one master setting (logo, title, footer…) is set to Modify or Hide in Step 2.

 10. Glossary

        

          
TermDefinition

          
            
XDPXML Data Package — the file format SAP uses for output form templates. Contains the XFA (XML Forms Architecture) structure defining layout and data bindings.

            
ADLCAdobe Document Lifecycle — SAP's name for the Maintain Form Templates Fiori app where XDP files are managed.

            
BAdIBusiness Add-In — SAP's extension mechanism allowing custom ABAP logic to be injected into standard processes, including output form data population.

            
CDS ViewCore Data Services View — SAP's data model layer used to expose business data for custom field derivation logic in ABAP.

            
RICEFWReports, Interfaces, Conversions, Enhancements, Forms, Workflows — the standard SAP project artefact classification. Output forms are type F.

            
TSDTechnical Specification Document — the mandatory Accenture deliverable documenting what was built, including Processing Logic for all custom fields.

            
_CUSTOM.xdpNaming convention for a modified XDP produced by the wizard, distinguishing it from the standard SAP pre-delivered XDP.

            
Mapping sheetA CSV or TSV file listing all custom fields for a form — technical name, data type, CDS view and derivation logic. The single source of truth for the wizard.

            
Derivation logicPlain-English description of how a custom field value is derived from SAP data — used by the wizard to generate ABAP SELECT, CONCATENATE or multi-join code.

            
Claude CodeAnthropic's command-line AI tool that can read and write files on local disk — used by the wizard for XDP patching and TSD population.

            
Output Parameter DeterminationSAP Fiori app where business rules determine which form template is used for a given output scenario (e.g. by company code, output type).
