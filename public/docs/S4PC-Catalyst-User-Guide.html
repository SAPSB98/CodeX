S4PC Catalyst

User Guide · Install on your desktop and run both pipelines — 12-step pipeline (new development) & Enhancement Pipeline (6 steps, existing code)

How to download S4PC Catalyst, set it up on your own Windows laptop, and run both pipelines.

Both run on your laptop. They don't need a connection to an SAP tenant, and they don't use API keys. Both stop at three checkpoints where you decide; neither carries on without your decision.

PipelineUse it whenYou provideYou get
12-step pipeline
(new development)		 Something new has to be built: an enhancement, report, interface, form or workflow A Functional Design (FD) Solution proposal, code, lint report, unit tests, Technical Design (TD), package with a tenant checklist
Enhancement Pipeline
(6 steps)		 Code that already exists has to change: a change request, an AMS enhancement or a bug fix, often on code another team built The new requirement, the existing TD and the current code Analysis of what the code does today, the change as a diff, review and tests, a revised TD, a deployment package

1. Before you start

Nothing else is installed: no pip packages, no Node.js, no admin rights.

2. Download

Get the tool from your lead in one of two ways:

  • Zip file: unzip it into a short local folder, for example C:\S4PC-Catalyst.
  • Git repository (if you've been given access): git clone <repository URL> C:\S4PC-Catalyst
Use a folder that isn't synced by OneDrive. Syncing can lock files while the pipeline writes them.

You should see START.cmd, SHUTDOWN.cmd, webapp\, mcp-server\ and ams\ in the folder.

3. Start the dashboard

  1. Open the folder in File Explorer and double-click START.cmd.
  2. A black window opens, and your browser opens at http://127.0.0.1:8321.
  3. Leave the black window open while you work. Closing it stops the dashboard.

If port 8321 is already in use, for example because you have a tunnel to the shared dashboard open, start on another port. Open Command Prompt and run:

cd /d C:\S4PC-Catalyst
set S4PC_UI_PORT=8322
START.cmd

Then open http://127.0.0.1:8322.

Quick check that it works: open Playground in the sidebar, run a release check on I_MaterialStock, and you should get LIKELY_RELEASED with evidence catalog_hit.

4. Run the 12-step pipeline (new development)

4.1 Start a run

  1. Open FD Intake in the sidebar.
  2. Under Add an FD document, pick your FD (.docx, .pdf, .txt or .md) or paste its text.
  3. Click ▶ Run pipeline.
  4. Open Workflow Explorer and pick your run. The step cards update as the run progresses.

4.2 What each step does and what you get

StepWhat happensOutput in output\<RUN-ID>\
1 IntakeClassifies the object (RICEFW type), maps scope items, lists open questions for the functional consultant01-discovery.md
2 Solution ProposalSplits the requirement into capabilities and rates each option (key user, developer, side-by-side or a mix) on feasibility, fit and cost; proposes the names of every custom object02-solution-proposal.md
3 Object InventoryChecks every SAP object in the design against the released-object catalog03-release-verdicts.md
4 Gate 1 · Release CheckBlocks the run if any object is not released—
5 ✋ Checkpoint 1 · SolutionYou approve the approach and lock the object namesdecisions\
6 BuildWrites the code from the approved proposal, using the locked names04-build.md
7 Gate 2 · Code Review + ✋ Checkpoint 2Clean-core and security review; findings are fixed and re-reviewed; you approve the code05-code-review.md
8 LintScans the code against the ABAP Cloud rules06-lint.md
9 Unit Test DesignABAP Unit tests mapped to the acceptance criteria07-unit-tests.md
10 Technical DesignThe TD, written from the code that was built, with a tenant verification checklist08-technical-design.md
11 Gate 3 · Peer Review + ✋ Checkpoint 3A challenger tries to break the design; you accept the delivery09-peer-review.md
12 PackageDeliverables list, transport order, go-live checklist; lessons saved for future runs10-package.md

4.3 Answering a checkpoint

When the run reaches a checkpoint, an amber decision panel appears at the top of the run in Workflow Explorer:

  • ✓ Approve: the run continues.
  • ✎ Adjust: write what should change in the notes. The pipeline reworks that part and asks again.
  • ✕ Reject: the run stops at this point.

At Checkpoint 1 you also lock the custom object names (Approve & lock names). At Checkpoint 2 you can comment on individual files, or Approve code as-is.

5. Run the Enhancement Pipeline (existing code)

5.1 Try the demo first

Open Enhancement Pipeline in the sidebar. Under Bundles you'll find AMS-DEMO-001, a small supplier-rating app with a change request ("low ratings need a comment"). Press Start run and follow it through to the end once before using your own code.

5.2 Create your enhancement

Under Enhancement, fill in:

FieldWhat to give
Enhancement IDYour ticket or CR number, for example CR-1234
1 · Requirement or CR documentExactly one file: .docx, .pdf, .md or .txt
2 · Existing technical designThe TD as it is, even if it's out of date (recommended)
3 · Current codeThe source of the objects being changed, as files or one .zip. Only the objects being changed are needed; if more turn out to be needed, the pipeline asks for them by name at Checkpoint 1.
Code copied from tenantWhich tenant the code came from, for example development
Same as production?Yes, no or not sure

Click Create bundle. The enhancement then appears under Bundles; press Start run.

Why the code and not only the TD: the TD says what was designed, but the code is what actually runs. A hotfix nobody documented lives only in the code, and a change built from the TD alone would quietly remove it.
Never upload passwords, keys, tokens, or business data with personal details. The upload blocks the credentials it recognises.

5.4 Answering a checkpoint

The checkpoint box says in plain English what was done and what you need to decide. Answer with Approve, Adjust (with notes) or Reject.

Under Deliverables, Documents holds the main reports and Code changes shows what changed in each file. The Technical files list can usually be ignored.

If a step fails before it reaches its checkpoint, the page shows the error and a Retry phase button. Retrying never records a decision twice.

6. Running from Claude Code instead of the dashboard

From the tool folder, in Claude Code:

  • 12-step pipeline: /run-pipeline input/<your FD file>
  • Enhancement Pipeline: /ams-change ams/input/<ID> (create the folder first with python -I ams/ams_tool.py init <ID>)

You then answer the checkpoints in the chat.

7. Stopping

  • Double-click SHUTDOWN.cmd, or close the black window.
  • If you started on a different port (section 3), SHUTDOWN.cmd reports "not running". Close the black window, or press Ctrl+C in it, instead.

Your runs stay in output\ and ams\output\ and are there the next time you start.

What you seeWhat to do

Pages stay on "Loading…"Refresh the page. If it persists, stop and start the dashboard.
▶ Run pipeline says the CLI isn't foundCheck that claude --version works in a new Command Prompt. If Claude Code is installed somewhere unusual, run set S4PC_CLAUDE_BIN=<full path to claude.exe> before START.cmd.
A step fails with "version 2.1.280 or newer is required"Run claude update, then Retry phase (Enhancement) or Re-run (12-step)
"The latest phase ran without the MCP server"Expected on managed laptops, where policy blocks the governance server in background runs. The checks still run through the tool's command-line channel, and the note shows how many were made.
A Word document can't be readSave it as PDF or plain text and upload that instead

9. Good to know

  • Clean core is enforced: only SAP-released APIs, CDS views and BAdIs are used. No BAPIs and no classical ABAP.
  • The results still need checking in your tenant: each package ends with a tenant verification checklist. Tests are designed and checked by the pipeline but run in ADT, in your system.
  • Your files stay on your laptop: inputs, outputs and decisions are files in the tool folder, and every decision is recorded in the run's run.json and decisions\ folder. To do the work, the text of your documents and code is processed by Claude through your organisation's Claude Code account.
