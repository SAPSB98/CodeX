General FAQs

Common questions about the GrowActivAIte platform, access, supported browsers, and how to get help.

Q1What is GrowActivAIte and what problem does it solve?

GrowActivAIte is Accenture's AI-powered delivery acceleration platform for SAP S/4HANA Public Cloud implementations. It bundles 13 pilot-ready AI agents that automate time-consuming, repetitive tasks across every phase of an SAP project — from security setup and business process documentation in the Discover & Prepare and Explore phases, through technical development and testing in Realize, to production support in the Run phase.

By automating artefact generation, configuration guidance, and defect analysis, the platform reduces manual effort, accelerates delivery timelines, and promotes consistency across project teams.

Q2How do I access the GrowActivAIte platform?

The platform is publicly accessible — no login, SSO, or Accenture credentials are required to open it. Simply open the link in any modern browser:

Platform URL: https://sapsb98.github.io/CodeX/

Note that individual agents may have their own credential requirements once launched:

  • Claude.ai-hosted agents — require an Accenture enterprise account when you click Launch
  • Accenture Media Exchange / SharePoint links — require your Accenture credentials
Q3Do I need a Claude.ai account to use these agents?

Yes, for most agents. The majority of agents in GrowActivAIte are hosted directly on Claude.ai as artifacts. When you click Launch Agent, it opens Claude.ai in your browser and you will need to sign in with a Claude.ai account.

The GrowActivAIte platform itself (the dashboard) requires no account — it is just a navigator to the agents. The Claude.ai account requirement kicks in only when you launch an individual agent.

Q4Which browsers and devices are supported?

GrowActivAIte is optimised for desktop use. Supported browsers:

  • Google Chrome 110+ (recommended)
  • Microsoft Edge 110+ (Chromium-based)
  • Mozilla Firefox 109+
  • Safari 16+ (macOS/iOS)

Internet Explorer is not supported. Mobile browsers are functional for viewing outputs but the agent wizard interfaces are optimised for screens wider than 1024px. Disable browser extensions that block JavaScript or intercept network requests, as these may break the streaming output panel.

Q5Can I use GrowActivAIte outside the Accenture network?

Yes, fully. The GrowActivAIte platform is hosted on GitHub Pages and is publicly accessible from any network, anywhere in the world — no VPN required.

However, some content linked from the platform does require Accenture credentials or VPN:

  • Accenture Media Exchange videos (e.g., Joule demo videos) — require Accenture login
  • Accenture SharePoint / Stream links — require Accenture credentials and may need VPN depending on your location
  • Claude.ai agents — accessible from any network with a Claude.ai Accenture enterprise account
Q6What data can I safely enter into the agents?

Follow Accenture's Data Classification Policy at all times:

  • Allowed: Business process names, functional requirements, technical specifications, non-sensitive configuration parameters, anonymised test data.
  • Not allowed: Personally Identifiable Information (PII), client credentials, production system passwords, financial data not approved for AI processing, data classified as Restricted or Confidential without explicit approval.
Important: Never paste live production credentials, client employee data, or payment card data into any agent input field. When in doubt, consult your project's Data Privacy Lead.
Q7How do I report a bug, incorrect output, or platform issue?

If you encounter a bug, an unexpected output, or any platform issue, please submit your feedback directly to the GrowActivAIte support team at:

s4_hana_public_cloud_growactivaite_support_group@accenture.com

When submitting, please include:

  1. The agent name where the issue occurred
  2. A brief description of the input you provided
  3. What you expected vs. what happened
  4. A screenshot if possible
Q8Are the outputs from AI agents reviewed before use?

Yes — all AI-generated outputs require human review before they are used in deliverables or submitted to clients. The agents accelerate drafting; they do not replace expert judgement. Functional leads, architects, or senior consultants must validate artefacts for accuracy, completeness, and client-specific context before sign-off.

Outputs should be treated as first drafts that need review and refinement, not final documents.

Q9Is there a demo available for the platform?

Yes! If you would like a live walkthrough or demo of the GrowActivAIte platform and its agents, please reach out to the support team at:

s4_hana_public_cloud_growactivaite_support_group@accenture.com

The team will be happy to arrange a session tailored to your team's needs and workstream.

Orion Agent – Prepare Phase I
Discover & Prepare Security Agent 5 Sub-Bots
Q1What does this agent do?

The Orion Agent – Prepare Phase I is a security-focused orchestration agent that automates five critical system setup and configuration tasks during the Discover & Prepare phase of an SAP S/4HANA Public Cloud project. It operates through five specialised sub-bots:

  • SBPA Automation Project MTAR: Automates the creation and export of SAP Build Process Automation (SBPA) Multi-Target Application (MTAR) project artefacts, reducing manual packaging effort.
  • CALM Project Set-up: Guides users through configuring an SAP Cloud ALM (CALM) project, including task lists, scope items, and team assignments.
  • CBC Set-up: Automates Cenral Business Configuration (CBC) environment setup steps, ensuring consistency across tenants.
  • Joule Enablement: Steps through the configuration tasks needed to activate and configure SAP Joule, Accenture's AI copilot entry point for S/4HANA.
  • User Provisioning: Generates and validates user provisioning scripts and role assignment templates for the initial system population.

Orion consolidates what previously required multiple consultants working in separate tools into a single guided, AI-assisted workflow.

Q2Who should use it?

The Orion Agent is intended for:

  • Basis / Security Consultants responsible for system setup and role design in the Prepare phase
  • Technical Leads overseeing tenant configuration and infrastructure readiness
  • Project Managers who need to track system readiness milestones in Cloud ALM
  • Delivery Leads wanting a consolidated view of Prepare phase configuration status

Familiarity with SAP BTP, Cloud ALM, and basic S/4HANA security concepts is recommended before using this agent.

Q3What inputs do I need to provide?

Inputs vary by sub-bot. The most common required inputs are:

  • SAP BTP Subaccount details: Subaccount ID, region, subdomain name
  • Cloud ALM tenant URL and API credentials (service key or OAuth client)
  • Project metadata: Project name, go-live date, scope items, country/region
  • System landscape details: Development, Quality, and Production system IDs
  • User list (for User Provisioning): CSV or Excel file with employee IDs, names, email addresses, and desired roles
  • Joule entitlement details: BTP entitlement name and service plan confirmed by your SAP account team
The agent will prompt you step-by-step for each input. You do not need to prepare all inputs upfront — the sub-bot wizard walks you through sequentially.
Q4What outputs will I get?
  • SBPA sub-bot: Downloadable MTAR project file and a configuration validation checklist
  • CALM sub-bot: Pre-populated Cloud ALM project setup guide and task assignment summary
  • CBC sub-bot: CBC configuration checklist with step completion status and export-ready configuration notes
  • Joule sub-bot: Joule activation checklist and a configuration runbook in Word/PDF format
  • User Provisioning sub-bot: Role assignment matrix, provisioning script (compatible with Identity Authentication Service / IAS), and an audit log template
Q5How do I access it?

Log in to the GrowActivAIte platform, navigate to the Discover & Prepare phase tab, and select the Orion Agent tile. Choose the sub-bot you wish to run from the sub-bot selector panel on the left. Each sub-bot has an independent guided wizard; you may run them in any order, though the recommended sequence is: CALM → CBC → SBPA → Joule → User Provisioning.

Q6What are the prerequisites?
  • Active SAP BTP Global Account with subaccounts provisioned for Dev/QA/Prod
  • Cloud ALM tenant provisioned and accessible
  • SAP S/4HANA Public Cloud tenants provisioned (at minimum Dev)
  • Service keys or OAuth credentials for Cloud ALM API (your Basis Lead must generate these)
  • Your Accenture GrowActivAIte login with the Security Agent role assigned
  • User data file ready in the supported CSV template format (downloadable from the agent's Help section)
Q7What should I do if something doesn't work as expected?
  • CALM/CBC connectivity errors: Verify that the service key is valid and not expired. Re-generate via BTP cockpit if needed.
  • MTAR generation fails: Confirm you have the SBPA Developer role in BTP and that the project name contains no special characters.
  • Joule sub-bot shows missing entitlements: Confirm Joule is entitled in your BTP Global Account with your SAP Account Executive.
  • User Provisioning CSV rejected: Re-download the CSV template from the agent's Help panel — column headers are case-sensitive.
  • For all other issues, use the in-app Feedback button or raise a ServiceNow ticket as described in the General FAQs (Q7).

Agent 02
BRRGM – Business Roles Requirement Gathering Matrix Generator
Discover & Prepare Security Security Agent
Q1What is BRRGM?

BRRGM (Business Roles Requirement Gathering Matrix Generator) is an Accenture internal tool built for the SAP S/4HANA Public Cloud Security practice. It automates the generation of the Business Roles Requirement Gathering Matrix — a structured Excel workbook that maps in-scope Fiori apps to business process roles. This gives Functional teams a clear baseline to validate requirements with their client process leads, and gives the Security team unambiguous, confirmed inputs to build business roles — eliminating back-and-forth and reducing rework during role design.

Q2Who should use this tool?
  • Functional Consultants — to review and validate Fiori app assignments against their business process scope before sign-off with client process leads.
  • Security Architects / Leads / Consultants — to govern the requirements baseline and ensure role design aligns with the agreed process scope. To receive confirmed, structured role requirements and build business roles without ambiguity or repeated clarification cycles.
Q3Does the tool require any installation?

No. BRRGM is a single HTML file (S4HANA Cloud BRRM Generator.html) that runs entirely in your browser. Simply open the file in Google Chrome or Microsoft Edge — no server, no installation, and no internet connection is required.

Q4Which browsers are supported?

Google Chrome and Microsoft Edge (Chromium-based). The tool uses browser APIs (File System Access API) that are only available in these browsers. Firefox, Safari, and Internet Explorer are not supported.

Q5Is any data sent to a server or the internet?

No. All processing happens locally in your browser. The input file is read locally, the matrix is generated in-memory, and the output Excel file is saved directly to your machine. No data is transmitted externally.

Q6What input file does the tool require?

The tool requires a SAP S/4HANA scope Excel file — typically the Process Steps or Solution Activities export from SAP Cloud ALM or the client's scope definition file. This file contains columns such as LOB (Line of Business), Business Area, Scope Item ID, Scope Item Description, Solution Activity, Fiori App ID, Fiori App Name, and Business Role ID.

Q7What format must the input file be?

The file must be in Excel format (.xlsx or .xls). It should contain a header row and one row per Fiori app/role combination in scope. The tool auto-detects column headers using partial matching, so minor naming variations (e.g. "Fiori App" vs "Fiori App ID") are handled automatically.

Q8Does the tool support multiple sheets in the input file?

The tool reads the first non-empty sheet it finds that contains the expected column headers. If your scope data spans multiple tabs, consolidate them into a single sheet before uploading.

Q9What if my input file is missing some columns?

The tool performs flexible column detection and will skip optional columns if they are absent (e.g. Fiori Semantic Action, L4 Task / Activity). Required columns — Fiori App ID, Fiori App Name, LOB, and Scope Item Description — must be present. If they are missing, the log panel will show a warning.

Q10My LOB column uses "&" instead of "and" — will the tool still match taxonomy entries?

Yes. The tool normalises LOB values before matching: "&" is converted to "and", separators (/, -, .) are treated as spaces, and comparison is case-insensitive. So "Sourcing & Procurement" will correctly match the taxonomy entry "Sourcing and Procurement".

Q11What are the steps to generate the workbook?
  1. Step 1 — Upload File: Click "Choose file" and select your scope Excel file.
  2. Step 2 — Select Countries: Choose all countries in scope for this implementation.
  3. Step 3 — Select Scope Items: Review and confirm which Scope Item IDs are in scope.
  4. Step 4 — Generate: Click the Generate button. The tool processes the file and produces the Excel workbook.
  5. Step 5 — Download: Once generation is complete, click Download to save the BRRGM workbook to your selected folder.
Q12How long does generation take?

For a typical scope file with 2,000–10,000 rows, generation takes 10–60 seconds depending on the number of Fiori apps and countries. A progress bar and log panel show real-time status. Very large files (20,000+ rows) may take up to 2–3 minutes.

Q13Can I re-generate with different settings without re-uploading the file?

Yes. After the first generation the uploaded file remains loaded. You can change country or scope item selections and click Generate again without re-uploading.

Q14What does the log panel show during generation?

The log panel shows a step-by-step trace of the generation process including: number of rows read, LOBs matched to the taxonomy, number of custom role columns created, country-scoped rows detected, and any warnings about missing data. Reviewing the log is useful for verifying the output is complete and correct.

Q15What sheets does the generated workbook contain?
  • ReadMe — Instructions and column descriptions. Read this sheet first.
  • Change Log — Version history. Log every change with version number, date, author, and description.
  • CustomBusinessProcRolesMatrix — Core deliverable. One row per in-scope Fiori app; process role columns show X where access is required.
  • HR Job Roles Mapping — Cross-reference matrix mapping process roles to standard HR job titles.
  • SODMatrix — Segregation of Duties conflict reference. One row per conflicting Fiori app pair.
  • Org.Elements — Organisational data by country (Company Code, Plant, Purchasing Org, etc.).
  • SolutionActivityMap-Reference — Lookup table mapping each Fiori app to its SAP Solution Activity.
Q16What is the CustomBusinessProcRolesMatrix?

The CustomBusinessProcRolesMatrix is the primary deliverable. Each row represents a unique in-scope Fiori app. The dynamic process role columns are derived from the L3 Process values in the scope file — one column per unique process. An X in a cell means that process role requires access to that Fiori app. Functional Leads review each row and populate the Validate Fiori App Requirement, Functional Restriction Required, Business Process Owner (BPO), and comment columns.

Q17How does the tool decide which HR titles to mark with X?

X marks are auto-populated using two rules: (1) Cross-functional titles — IT Manager, Business Analyst, Project Manager, and ERP Administrator — are marked for every process role. (2) LOB-specific titles — e.g. Finance process roles are marked for Chief Financial Officer, Finance Director, Finance Manager, Financial Controller, and Treasury Manager. Functional Leads should review and adjust the X marks to reflect their organisation's actual assignments before sign-off.

Q18What is the SODMatrix?

The SODMatrix sheet lists pairs of Fiori apps that create a Segregation of Duties (SOD) conflict when assigned to the same user. The pairs are generated automatically from the apps in scope. Reviewers should check this sheet before finalising role assignments to ensure no conflicting app pairs are combined in a single custom role.

Q19What is "Validate Fiori App Requirement" and how do I fill it?

This column captures the review outcome for each Fiori app row. Select one of: In-Scope, Out-of-Scope, or TBD. Every row must have a value before the matrix is submitted for security role build.

Q20What format should I use for comment columns?

Use the format: [Reviewer Name / Date]: Comment text. For BPO Approval Comments, prefix with the outcome: [APPROVED / REJECTED / ON-HOLD] — [Name] — [Date]: Comment.

Q21How does country scoping work?

When you select countries in Step 2, the tool adds one column per country showing whether each Fiori app is applicable to that country. Classification uses three detection methods: (1) App ID suffix conventions, (2) App title keywords (e.g. "Japan", "Russia"), and (3) SAP business role suffix patterns. Hardcoded overrides in APP_COUNTRY_OVERRIDE take absolute priority.

Q22Why are some SAP roles not appearing in the output?

The tool filters out: (1) Critical / admin roles (SAP_BASIS_*, test user roles); (2) TBR (To Be Reviewed) configuration-level roles; (3) Excluded apps listed in EXCLUDED_APP_IDS — pure configuration or admin tools such as Data Replication, Migration Cockpit, and Communication Arrangements.

Q23Excel shows a repair dialog when I open the generated file — what should I do?

If Excel reports "Repaired Records", click OK and review the file. This issue has been resolved in tool version 2.x. Make sure you are using the latest version of the BRRGM HTML file. If the issue persists, contact the tool administrator.

Q24The tool does not respond after I click Generate — what should I check?

Ensure you are using Chrome or Edge. Then check: (1) the file was successfully uploaded, (2) at least one country is selected, (3) at least one scope item is selected. If the issue persists, open the browser developer console (F12), check for error messages, and contact the tool administrator with those details.

Q25Can I save to a network or SharePoint folder directly?

Yes. The tool supports the File System Access API, allowing you to select a folder — including OneDrive-synced or mapped network folders — as the download destination. Click the folder icon next to the Download button to choose a directory; all subsequent downloads in that session will go there automatically.

Q26How is the tool distributed and how do I get the latest version?

The tool is distributed as a single standalone HTML file: S4HANA Cloud BRRM Generator.html. Share it via your team SharePoint, OneDrive, or email. Contact the Accenture S/4HANA Security practice tool owner to receive the latest version. The version number is shown in the footer of the tool interface.

Q27Can the tool be customised for a specific client?

Yes. The tool source supports several customisation points: LOB name overrides (LOB_RECLASSIFY), country-specific app overrides (APP_COUNTRY_OVERRIDE), excluded app IDs (EXCLUDED_APP_IDS), and the LOB-to-job-role taxonomy (LOB_JOB_ROLE_TAXONOMY). Contact the tool administrator for guidance.

PMO Agent – Project Charter
Discover & Prepare Project Governance PMO Agent
Q1What does this agent do?

It turns a Statement of Work (SOW) into a review-ready first-draft SAP PM_15 Project Charter. It reads the SOW and any supporting documents, captures the facts with their sources, then drafts each of the 11 charter components, checks each against a fixed specification, and revises until every required item is covered.

It works strictly from what your documents contain — it never invents content. Where the SOW is silent, it writes "not covered in SOW" rather than filling the gap. Financial values are excluded throughout. Alongside the charter it produces a companion Annex (a coverage report, the source-tagged fact registry, a fill checklist, and PM review notes).

The output is a strong first draft for a human to review and complete — not a signed or final document.

Q2Who should use it?

It is built for the people who normally author or review project charters:

  • Project / Programme Managers preparing the initial charter for a new SAP engagement.
  • PMO and delivery leads who need a consistent, spec-complete first draft to review and refine.
  • Anyone responsible for turning a signed SOW into a governance-ready charter quickly.

No technical skill is needed — you attach a document and press one button. A reviewer with SOW knowledge then completes and validates the draft.

Q3What inputs do I need to provide?

The SOW is the only required input. The other three below are usually already covered within the SOW — but if your SOW does not contain them (or covers them thinly), it is recommended to add them as separate inputs:

  • SOW (recommended primary) — the Statement of Work. A scrubbed SOW is recommended (see prerequisites).
  • Risks / Issues — a risk or issue log, if maintained separately.
  • Stakeholder Register — sponsor, steering board, process owners, key users.
  • Process Scope — in-scope lines of business, scope items, integrations, migration.

Files can be PDF, Word (.docx), PowerPoint (.pptx), Excel, or images — or you can paste text directly. Tables and schedules that appear inside pictures are read as well.

Q4What outputs will I get?

Two Word documents, produced together:

  • The Project Charter (SAP PM_15) — cover, document identification, the full charter across all 11 components, and authorization & acceptance signature blocks.
  • A companion Annex — an audit trail containing the SOW coverage report, the source-tagged fact registry, a consistency check, a fill checklist of any redacted values, and PM review notes.

Everything is source-traceable — each line ties back to the SOW clause, page, or figure it came from. Values that were scrubbed from the SOW appear as [FILL: …] tokens, gathered in the Annex checklist so a reviewer can complete them in one pass. The average run takes on the order of minutes rather than the days manual authoring can take.

Q5How do I access it?

It runs live in your browser — there is nothing to install. Open the shared link, attach your SOW (or paste its text), and press "Run agent loop." You can watch the agent work through its steps, then download the charter and Annex when it finishes.

It runs on any machine with a modern browser. Because updates are shared as new versions, make sure you are using the latest link provided for your pilot.

Q6What are the prerequisites?
  • A signed or near-final SOW — the richer the SOW, the more complete the draft.
  • A scrubbed SOW is recommended — remove or mask client-identifying details before running, after alignment with your project / client team. The agent processes the document in-session and stores no document content, but scrubbing keeps sensitive data out of processing in the first place.
  • A modern web browser — no installation, plug-in, or license key required.

There is no setup beyond opening the link. Note that scrubbed values are not lost — they surface as [FILL: …] tokens for a reviewer to complete.

Q7What should I do if something doesn't work as expected?

A few common situations and what they mean:

  • A section reads "not covered in SOW" — this is by design, not an error: the SOW genuinely did not contain that information. Add the relevant document or complete it during review.
  • The charter looks thin — the SOW may be light on that topic, or a supporting input (Risks, Stakeholders, Process Scope) would help. Add it and re-run.
  • A value shows as [FILL: …] — that value was scrubbed or absent; complete it using the Annex fill checklist.
  • A figure is flagged "UNREADABLE" — a chart or image was too dense to read reliably; check that source manually.
  • A run is taking long, or you want to stop — press Stop; the run halts and you can still download whatever was drafted so far.

Above all, treat the output as a first draft: review it against the SOW, complete the flagged items, and validate before use. If a problem persists, report it to your pilot lead with the SOW and a note of what you expected.

Agent 04
L4 Plan Agent (MVP)
Discover & Prepare Project Planning PMO Agent
Q1What does this agent do?

It turns a list of SAP scope-item IDs and project dates into a review-ready first-draft SAP Activate Level-4 (L4) project plan for S/4HANA Public Cloud. This MVP produces a deterministic plan: it reconciles the scope against the SAP live feed and a built-in library, classifies project size, sizes each phase, sequences the work by dependency, schedules tests, workshops and workstreams, and applies SAP PM_19 scheduling rules.

It works strictly from library data, the live feed and your inputs — it never invents. Unknown items are flagged "pending" and effort figures are estimates (AI-estimated ones flagged [AI-est]). It also includes an AI review / co-pilot (the co-pilot can export a separate AI-proposed plan); those AI actions run inside Claude or with a pasted Anthropic key.

The output is a strong first draft for PM review and completion — not an approved baseline.

Q2Who should use it?

It is built for the people who normally plan or review SAP delivery:

  • Project / Programme Managers preparing an initial L4 schedule for a new SAP engagement.
  • PMO and delivery leads who need a consistent, rules-based first-draft plan to review and refine.
  • Solution and scope leads turning a scope-item list into a sequenced, sized plan quickly.

No technical skill is needed — enter scope, set dates, press Generate. A reviewer with delivery knowledge then completes and validates the draft.

Q3What inputs do I need to provide?

The SAP live feed and your scope IDs are required (plus a project start date); everything else refines the plan:

  • SAP live feed — imported first, via the SAP Live Fetch browser extension: the L4 Scenario Bundle (live scope, country availability, cross-SID dependencies and configuration activities).
  • Scope Item IDs — pasted as text, or browsed and ticked by line of business.
  • Project parameters — start date, optional end date, project type, and SIT / UAT test cycles (sprint duration and holidays use MVP defaults).
  • Project shape — Prepare / Explore / Deploy profile tags.
Q4What outputs will I get?

The deterministic engine produces the L4 plan as Excel (Download L4 Plan (Excel)) — columns include WBS, L1 Phase, L2 Workstream, Scope Item ID, Task, Activity Type, Owner, Team, Start/End Date, Start/End Sprint, Days, Work Days, Predecessor, Go-Live Relevance, Priority, LOB, Config Days, UT Days and Purpose.

On Generate you get a Project sizing & fit-check popup; the results panel then shows the Download button and the AI review / co-pilot. The AI co-pilot's separate AI proposal (Export AI proposal) is also included; it runs when the AI layer has model access (inside Claude or a pasted key).

Everything is traceable — each task ties back to its scope item and the rule that placed it. Effort is flagged [AI-est] / [AI-draft] / pending where applicable. A run takes on the order of seconds to minutes, rather than the days manual planning can take.

Q5How do I access it?

It runs live in your browser — the app itself needs nothing installed, though the required live SAP feed uses a separate SAP Live Fetch browser extension (installed once). Open the shared link, import the live feed, enter scope and dates, press Generate, then download the plan.

Because updates are shared as new versions, make sure you are using the latest link provided for your pilot.

Q6What are the prerequisites?
  • The SAP live feed — the L4 Scenario Bundle, pulled by the SAP Live Fetch browser extension (a one-time install) and imported first.
  • A scope-item list — the more accurate the scope, the better the plan.
  • Project dates and basic parameters — start date, optional end date, project type, and SIT / UAT test cycles.
  • A modern web browser — no install or license key for the app itself (the required live SAP feed uses the SAP Live Fetch extension, a one-time install).

There is no setup beyond opening the link. Unknown scope IDs surface as "pending" for you to resolve, and effort figures are estimates (AI-estimated ones flagged [AI-est]).

Q7Is the AI review / co-pilot available in this MVP?

Yes. Both AI review and AI co-pilot (which can export a separate AI-proposed plan) are included in this MVP. Because they call the model, they run when the tool is opened inside Claude, or when you paste an Anthropic API key. The deterministic plan (Generate then Download L4 Plan (Excel)) needs no key and is fully reproducible. For key-free AI on plain hosting, deploy the provided gateway (main.py) and set PROXY_URL; the deterministic plan needs no key regardless.

Q8What should I do if something doesn't work as expected?
  • A scope ID reads "pending" — it is not in the library or the feed; add a library row, or confirm the ID (watch letter O versus zero).
  • The plan looks too short or too long — check the busiest-LOB effort, the [AI-est] days, and the size classification.
  • An overrun you can't remove — the work does not fit the dates; extend dates, cut scope, or add parallelism.
  • Effort shows [AI-est] — that is expected (SAP publishes none); review with workstream leads before baselining.
  • Dependencies look off — the live Availability feed is authoritative; confirm the live-vs-library difference.

Above all, treat the output as a first draft: resolve pending items, review the estimates and overruns, and validate against your delivery experience before baselining. If a problem persists, report it to your pilot lead with the inputs used and a note of what you expected.

PMO Agent – Onboarding & Offboarding (Resource Lifecycle Management)
Discover & Prepare Resource Management PMO Agent
Q1What does this agent do?

The Onboarding & Offboarding Agent manages the full lifecycle of project resources — from joining to exit — under a single governed process with a complete audit trail.

Key capabilities include:

  • Validates every request against live project, WBS, location and contact data
  • Routes approvals through a nine-state, role-gated workflow
  • Closes out assets, access and knowledge transfer on exit
  • Generates personalized notifications to all relevant stakeholders
  • Logs every write with actor identity and before/after values
  • AI assists in drafting and suggesting but never approves or sends autonomously
Q2Who should use it?

This agent is designed for the following personas:

  • Project Leads, Project Managers, Project PMOs, Project Ops Team & Delivery Leads — to onboard and offboard team members with structured approvals
Q3What inputs do I need to provide?

Project & Resource Details:

  • Project & WBS code, resource name & role
  • Start / end dates, last working day, exit reason & handover
  • Location, FTE, supervisor / lead / HR contact

Setup & Configuration (one-time admin):

  • Mandatory training, skills & resource levels
  • Assets & access systems
  • Email template & branding, recipient & trigger rules
  • Tracker CSV upload (seven master-data types, behind a mandatory dry-run)

This is an SAP SSO session refresh. The current version handles this automatically — it waits for the login tab to close, then retries the download.   • Industry context — adds sub-questions and considerations specific to the client's sector (Manufacturing, Retail, Pharma etc.).

Closing the browser tab stops the display, but the server continues generating in the background. To cancel completely, close the START.bat console window. Partially completed items are cached — restarting and generating again will only re-run the incomplete ones.
