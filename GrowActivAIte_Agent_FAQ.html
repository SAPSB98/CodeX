General FAQs

Common questions about the GrowActivAIte platform, access, supported browsers, and how to get help.

Q1What is GrowActivAIte and what problem does it solve?

GrowActivAIte is Accenture's AI-powered delivery acceleration platform for SAP S/4HANA Public Cloud implementations. It bundles 13 pilot-ready AI agents that automate time-consuming, repetitive tasks across every phase of an SAP project — from security setup and business process documentation in the Discover & Prepare and Explore phases, through technical development and testing in Realize, to production support in the Run phase.

By automating artefact generation, configuration guidance, and defect analysis, the platform reduces manual effort, accelerates delivery timelines, and promotes consistency across project teams.

Q2How do I access the GrowActivAIte platform?

The platform is publicly accessible — no login, SSO, or Accenture credentials are required to open it. Simply open the link in any modern browser:

Platform URL: https://sapsb98.github.io/CodeX/

Note that individual agents may have their own credential requirements once launched:

  • Claude.ai-hosted agents — require an Accenture enterprise account when you click Launch
  • Accenture Media Exchange / SharePoint links — require your Accenture credentials
Q3Do I need a Claude.ai account to use these agents?

Yes, for most agents. The majority of agents in GrowActivAIte are hosted directly on Claude.ai as artifacts. When you click Launch Agent, it opens Claude.ai in your browser and you will need to sign in with a Claude.ai account.

The GrowActivAIte platform itself (the dashboard) requires no account — it is just a navigator to the agents. The Claude.ai account requirement kicks in only when you launch an individual agent.

Q4Which browsers and devices are supported?

GrowActivAIte is optimised for desktop use. Supported browsers:

  • Google Chrome 110+ (recommended)
  • Microsoft Edge 110+ (Chromium-based)
  • Mozilla Firefox 109+
  • Safari 16+ (macOS/iOS)

Internet Explorer is not supported. Mobile browsers are functional for viewing outputs but the agent wizard interfaces are optimised for screens wider than 1024px. Disable browser extensions that block JavaScript or intercept network requests, as these may break the streaming output panel.

Q5Can I use GrowActivAIte outside the Accenture network?

Yes, fully. The GrowActivAIte platform is hosted on GitHub Pages and is publicly accessible from any network, anywhere in the world — no VPN required.

However, some content linked from the platform does require Accenture credentials or VPN:

  • Accenture Media Exchange videos (e.g., Joule demo videos) — require Accenture login
  • Accenture SharePoint / Stream links — require Accenture credentials and may need VPN depending on your location
  • Claude.ai agents — accessible from any network with a Claude.ai Accenture enterprise account
Q6What data can I safely enter into the agents?

Follow Accenture's Data Classification Policy at all times:

  • Allowed: Business process names, functional requirements, technical specifications, non-sensitive configuration parameters, anonymised test data.
  • Not allowed: Personally Identifiable Information (PII), client credentials, production system passwords, financial data not approved for AI processing, data classified as Restricted or Confidential without explicit approval.
Important: Never paste live production credentials, client employee data, or payment card data into any agent input field. When in doubt, consult your project's Data Privacy Lead.
Q7How do I report a bug, incorrect output, or platform issue?

There is no formal ticketing system in place yet. If you encounter a bug, an unexpected output, or any platform issue, please reach out directly to the team via email:

  • Arpit Srivastava — arpit.c.srivastava@accenture.com
  • Swarnali Basu — swarnali.basu@accenture.com

When reaching out, please include:

  1. The agent name where the issue occurred
  2. A brief description of the input you provided
  3. What you expected vs. what happened
  4. A screenshot if possible
Q8Are the outputs from AI agents reviewed before use?

Yes — all AI-generated outputs require human review before they are used in deliverables or submitted to clients. The agents accelerate drafting; they do not replace expert judgement. Functional leads, architects, or senior consultants must validate artefacts for accuracy, completeness, and client-specific context before sign-off.

Outputs should be treated as first drafts that need review and refinement, not final documents.

Yes! If you would like a live walkthrough or demo of the GrowActivAIte platform and its agents, please reach out to:

Agent 01
Orion Agent – Prepare Phase I
Discover & Prepare Security Agent 5 Sub-Bots
Q1What does this agent do?

The Orion Agent – Prepare Phase I is a security-focused orchestration agent that automates five critical system setup and configuration tasks during the Discover & Prepare phase of an SAP S/4HANA Public Cloud project. It operates through five specialised sub-bots:

  • SBPA Automation Project MTAR: Automates the creation and export of SAP Build Process Automation (SBPA) Multi-Target Application (MTAR) project artefacts, reducing manual packaging effort.
  • CALM Project Set-up: Guides users through configuring an SAP Cloud ALM (CALM) project, including task lists, scope items, and team assignments.
  • CBC Set-up: Automates Cloud Business Configuration (CBC) environment setup steps, ensuring consistency across tenants.
  • Joule Enablement: Steps through the configuration tasks needed to activate and configure SAP Joule, Accenture's AI copilot entry point for S/4HANA.
  • User Provisioning: Generates and validates user provisioning scripts and role assignment templates for the initial system population.

Orion consolidates what previously required multiple consultants working in separate tools into a single guided, AI-assisted workflow.

Q2Who should use it?

The Orion Agent is intended for:

  • Basis / Security Consultants responsible for system setup and role design in the Prepare phase
  • Technical Leads overseeing tenant configuration and infrastructure readiness
  • Project Managers who need to track system readiness milestones in Cloud ALM
  • Delivery Leads wanting a consolidated view of Prepare phase configuration status

Familiarity with SAP BTP, Cloud ALM, and basic S/4HANA security concepts is recommended before using this agent.

Q3What inputs do I need to provide?

Inputs vary by sub-bot. The most common required inputs are:

  • SAP BTP Subaccount details: Subaccount ID, region, subdomain name
  • Cloud ALM tenant URL and API credentials (service key or OAuth client)
  • Project metadata: Project name, go-live date, scope items, country/region
  • System landscape details: Development, Quality, and Production system IDs
  • User list (for User Provisioning): CSV or Excel file with employee IDs, names, email addresses, and desired roles
  • Joule entitlement details: BTP entitlement name and service plan confirmed by your SAP account team
The agent will prompt you step-by-step for each input. You do not need to prepare all inputs upfront — the sub-bot wizard walks you through sequentially.
Q4What outputs will I get?
  • SBPA sub-bot: Downloadable MTAR project file and a configuration validation checklist
  • CALM sub-bot: Pre-populated Cloud ALM project setup guide and task assignment summary
  • CBC sub-bot: CBC configuration checklist with step completion status and export-ready configuration notes
  • Joule sub-bot: Joule activation checklist and a configuration runbook in Word/PDF format
  • User Provisioning sub-bot: Role assignment matrix, provisioning script (compatible with Identity Authentication Service / IAS), and an audit log template
Q5How do I access it?

Log in to the GrowActivAIte platform, navigate to the Discover & Prepare phase tab, and select the Orion Agent tile. Choose the sub-bot you wish to run from the sub-bot selector panel on the left. Each sub-bot has an independent guided wizard; you may run them in any order, though the recommended sequence is: CALM → CBC → SBPA → Joule → User Provisioning.

Q6What are the prerequisites?
  • Active SAP BTP Global Account with subaccounts provisioned for Dev/QA/Prod
  • Cloud ALM tenant provisioned and accessible
  • SAP S/4HANA Public Cloud tenants provisioned (at minimum Dev)
  • Service keys or OAuth credentials for Cloud ALM API (your Basis Lead must generate these)
  • Your Accenture GrowActivAIte login with the Security Agent role assigned
  • User data file ready in the supported CSV template format (downloadable from the agent's Help section)
Q7What should I do if something doesn't work as expected?
  • CALM/CBC connectivity errors: Verify that the service key is valid and not expired. Re-generate via BTP cockpit if needed.
  • MTAR generation fails: Confirm you have the SBPA Developer role in BTP and that the project name contains no special characters.
  • Joule sub-bot shows missing entitlements: Confirm Joule is entitled in your BTP Global Account with your SAP Account Executive.
  • User Provisioning CSV rejected: Re-download the CSV template from the agent's Help panel — column headers are case-sensitive.
  • For all other issues, use the in-app Feedback button or raise a ServiceNow ticket as described in the General FAQs (Q7).

Agent 02
Business Process Design L1 to L5
Explore Process Documentation
Q1What does this agent do?

The Business Process Design L1–L5 agent generates structured SAP business process documentation across five levels of detail — from high-level process groups down to granular task steps — using AI. It reduces the time functional consultants spend drafting process hierarchies from scratch.

  • L1 – Process Group: Top-level grouping (e.g., Order-to-Cash, Procure-to-Pay)
  • L2 – Process: Major processes within the group (e.g., Sales Order Management)
  • L3 – Process Variant / Scenario: Specific business scenarios (e.g., Standard Sales Order with Credit Check)
  • L4 – Process Step: Individual steps within a scenario (e.g., Create Sales Order in VA01)
  • L5 – Task / Activity: Detailed user actions, system responses, and decision points

The agent can generate the full L1–L5 hierarchy from a brief description or expand a partial hierarchy from an L1 or L2 input.

Q2Who should use it?
  • Functional Consultants (SD, MM, FI, HR, etc.) drafting process documentation during Explore workshops
  • Solution Architects defining the process scope and hierarchy for Fit-to-Standard sessions
  • Business Analysts translating client process requirements into SAP-aligned documentation
  • Delivery Leads reviewing process completeness prior to Fit-to-Standard workshops
Q3What inputs do I need to provide?
  • Industry / client sector (e.g., Manufacturing, Retail, Professional Services)
  • SAP module or process area (e.g., Sales & Distribution, Materials Management)
  • Starting level — specify whether you are starting from L1, L2, or providing a partial hierarchy for the agent to expand
  • Process description or scope statement (free text, 1–3 sentences is sufficient)
  • Optional: Client-specific terminology, country localisation requirements, or excluded process variants
Q4What outputs will I get?
  • Structured L1–L5 process hierarchy in a downloadable Word document and Excel spreadsheet
  • Process flow description in paragraph form (suitable for inclusion in a BRD or FDD)
  • Suggested SAP transaction codes (T-codes) and Fiori app references at L4/L5 level
  • Decision point and role/responsibility notes at L5 level
  • Optional: BPMN-compatible process notation export (XML) for import into tools such as Signavio or LeanIX
Q5How do I access it?

Log in to GrowActivAIte, navigate to the Explore phase tab, and click the Business Process Design L1–L5 tile. The agent opens a two-panel interface: the left panel accepts your inputs via a structured form; the right panel renders the generated hierarchy in real time as the AI produces it. Use the toolbar above the output panel to export in Word, Excel, or XML.

Q6What are the prerequisites?
  • GrowActivAIte login with the Functional Consultant or Solution Architect role
  • Basic knowledge of SAP S/4HANA process areas relevant to your project scope
  • Agreed project scope document (or at minimum a high-level scope list) to ensure the generated hierarchy aligns with the client's in-scope processes
Q7What should I do if something doesn't work as expected?
  • Generated hierarchy is too generic: Add more context in the process description field. Include the client's industry, sub-industry, and any specific variants (e.g., "intercompany sales with third-party delivery").
  • Wrong SAP module assumed: Explicitly specify the module (e.g., "SAP SD module, not MM") in the input form's module selector.
  • L5 tasks are missing or thin: Use the "Expand L5" button on individual L4 nodes to trigger a deeper generation pass.
  • Export fails: Try a different format (Word vs Excel). Clear browser cache if the download button is unresponsive.
  • Report persistent issues via the in-app Feedback button.

Agent 03
Fit to Standard – Material Generation
Explore Workshop Materials
Q1What does this agent do?

The Fit-to-Standard Material Generation agent automatically produces the workshop slide decks, facilitator guides, and Business Driven Configuration Questionnaire (BDCQ) content used during SAP Fit-to-Standard (FtS) sessions. These sessions are where the project team demonstrates standard SAP functionality to the client and captures configuration decisions and gaps.

The agent:

  • Generates FtS workshop agenda slides tailored to the in-scope process areas
  • Creates BDCQ questionnaire content — structured questions that capture the client's configuration choices for each scope item
  • Produces process demonstration scripts for the consultant facilitating the session
  • Generates gap capture templates for recording where standard SAP does not meet client requirements
Q2Who should use it?
  • Functional Leads and Consultants preparing FtS workshop materials
  • Solution Architects ensuring workshop coverage aligns with SAP scope items
  • Delivery / Project Managers reviewing workshop schedules and content completeness before client sessions
Q3What inputs do I need to provide?
  • Agreed scope item list — SAP S/4HANA scope item IDs (e.g., BJ5, 1GA) or process names
  • Client industry and country/region
  • Workshop date and duration (for agenda generation)
  • Attendee roles (e.g., Finance Director, Procurement Manager) — influences the language and depth of BDCQ questions
  • Optional: Client's existing AS-IS process notes or a brief description of known complexity areas
Q4What outputs will I get?
  • PowerPoint slide deck — FtS workshop agenda and process overview slides (Accenture-branded template)
  • Excel BDCQ — one worksheet per scope item with pre-populated configuration questions, answer options, and notes columns
  • Word facilitator guide — step-by-step session facilitation notes including demo script cues and expected client questions
  • Word gap log template — pre-structured table ready for gap capture during the session
Q5How do I access it?

In GrowActivAIte, go to the Explore phase tab and select Fit to Standard – Material Generation. The agent displays a multi-step form: (1) Scope Input, (2) Workshop Details, (3) Output Preferences. Complete each step and click Generate Materials. Generation typically takes 60–120 seconds depending on the number of scope items. Download links appear once generation is complete.

Q6What are the prerequisites?
  • Signed-off scope item list from your Engagement Lead or Solution Architect
  • GrowActivAIte login with the Functional Consultant role or higher
  • Access to the project's SharePoint or document repository to upload the generated materials for client sharing
Q7What should I do if something doesn't work as expected?
  • BDCQ questions seem irrelevant: Verify the scope item IDs entered are correct and match the SAP Scope Item Catalogue. Use the scope item ID lookup helper within the agent.
  • Slide deck uses wrong branding: Confirm your project profile has the correct client branding settings configured by the Delivery Lead in the platform's Project Settings.
  • Generation times out: Reduce the number of scope items per batch (max 15 recommended). Split large scope lists into multiple runs.
  • BDCQ Excel is empty: This typically indicates a scope item ID format error. Ensure IDs follow the format shown in the on-screen example (e.g., 1GA, BJ5).

Agent 04
Functional Design Document Phase 1
Explore Design Documentation
Q1What does this agent do?

The Functional Design Document (FDD) Phase 1 agent generates structured Functional Design Documents for SAP S/4HANA Public Cloud configuration. FDDs are formal deliverables that describe how SAP standard functionality will be configured to meet a client's specific business requirements — and where custom extensions (RCEFW) are needed.

The agent produces Phase 1 FDDs, which cover:

  • Business requirement description
  • Proposed SAP solution approach (standard configuration vs. extension)
  • Configuration parameters and settings to be applied
  • Integration touchpoints
  • Open questions and assumptions
  • Sign-off section for client and Accenture leads
Q2Who should use it?
  • Functional Leads responsible for producing configuration design documentation
  • Senior Functional Consultants drafting FDDs for their workstream
  • Solution Architects reviewing FDD quality and consistency across workstreams
Q3What inputs do I need to provide?
  • Business requirement description — paste the relevant requirement text from the client's BRD or BDCQ
  • SAP module / functional area (e.g., FI-GL, SD-OTC, MM-PUR)
  • Client name and project code (for document header population)
  • Relevant BDCQ answers — completed questionnaire answers from the FtS session inform the configuration approach
  • Known constraints or client-specific rules (optional free text)
  • Extension flag: Indicate if this requirement is expected to require an RCEFW object (the agent will flag this in the FDD)
Q4What outputs will I get?
  • A completed FDD Word document using the Accenture S/4HANA Public Cloud FDD template (v2.x)
  • An FDD summary table (Excel) suitable for inclusion in a project tracker or status report
  • A list of open questions that must be resolved before the FDD can be finalised
  • Related RCEFW identification: If an extension is flagged, the agent pre-populates the RCEFW object name and type for handoff to the RCEFW Builder agents
Q5How do I access it?

In GrowActivAIte, go to Explore phase, select the Functional Design Document Phase 1 tile. Paste or upload your requirement input, select the SAP module from the dropdown, and click Generate FDD. You can generate one FDD at a time or use the batch upload feature (CSV of requirements) to generate multiple FDDs in a single run.

Q6What are the prerequisites?
  • Completed BDCQ outputs from the FtS workshops (at least partially completed)
  • Access to the project's Business Requirements Document or scope item descriptions
  • GrowActivAIte login with the Functional Lead role assigned
  • Project code and client name confirmed in GrowActivAIte Project Settings
Q7What should I do if something doesn't work as expected?
  • FDD content is inaccurate for the SAP module: Ensure you have selected the correct module in the dropdown — similar requirement descriptions can produce different FDDs depending on the module context.
  • Template version is incorrect: Check with your Delivery Lead that your project is using FDD template v2.x; older templates (v1.x) are not supported by this agent.
  • Batch upload fails: Confirm the CSV follows the batch template format. Download the template from the agent's Help panel. Maximum 50 requirements per batch.
  • Generated FDD lacks detail: Provide more specific BDCQ answers and client constraints in the input fields. The richer the input, the more detailed the output.

Agent 05
RCEFW Builder – Technical Design
Realize Technical Documentation RCEFW Builder
Q1What does this agent do?

The RCEFW Builder – Technical Design agent generates Technical Design Documents (TDDs) for RICEFW objects — Reports, Conversions, Enhancements, Forms, Workflows, and Interfaces — required in an SAP S/4HANA Public Cloud implementation. Given the functional specification from an FDD, it produces a structured technical document describing the development approach, data model, logic design, error handling, and test considerations for the object.

Q2Who should use it?
  • Technical Leads and Senior ABAP/BTP Developers who oversee RCEFW object design
  • Technical Architects reviewing design decisions for extensibility and upgrade safety
  • Functional Leads who want to review the technical approach before formal sign-off
Q3What inputs do I need to provide?
  • FDD reference number and content (paste text or upload the FDD document)
  • RCEFW object type — Report, Conversion, Enhancement, Form, Workflow, or Interface
  • Technical approach preference — RAP (ABAP RESTful), CAP (BTP Cloud Application Programming), or Classic ABAP (where permitted)
  • Integration endpoints (source/target systems, APIs) if applicable
  • Performance requirements — expected data volumes, response time SLAs
  • Development system ID and transport landscape details
Q4What outputs will I get?
  • Technical Design Document (TDD) in Word format — covers object overview, technical approach, data dictionary, logic pseudocode, error/exception handling, authorisation objects, and unit test scenarios
  • RCEFW object register entry (Excel row) ready to be added to the project's RCEFW tracker
  • Estimated development effort (in person-hours) based on complexity scoring
  • Handoff summary for the code generation agents (Agents 06, 07, 08)
Q5How do I access it?

In GrowActivAIte, navigate to the Realize phase tab, open the RCEFW Builder section, and click Technical Design. Upload or paste your FDD, complete the object type and technical preference form fields, then click Generate TDD. The output renders in the right panel; download when complete.

Q6What are the prerequisites?
  • Completed and reviewed FDD from the Explore phase (Agent 04 output or equivalent)
  • GrowActivAIte login with the Technical Developer or Technical Lead role
  • Agreed development strategy (RAP vs. CAP vs. Classic) confirmed by your Technical Architect
Q7What should I do if something doesn't work as expected?
  • TDD is too high-level: Provide more detail in the FDD input — especially data flow, business logic rules, and error scenarios.
  • Wrong development approach suggested: Override the agent's recommendation via the Technical Approach dropdown and regenerate.
  • Effort estimate seems off: The estimate is a guide only. Adjust in your project plan based on team experience. Use the Feedback button to flag consistently inaccurate estimates so the model can be calibrated.

Agent 06
RCEFW Builder – RAP Code Generation
Realize ABAP RAP RCEFW Builder
Q1What does this agent do?

The RCEFW Builder – RAP Code Generation agent generates ABAP code following the RESTful Application Programming (RAP) model for SAP S/4HANA. RAP is SAP's recommended, upgrade-stable development model for S/4HANA extensions. The agent produces:

  • CDS (Core Data Services) view definitions — interface views, projection views, and metadata extensions
  • Behaviour Definition Language (BDEF) files for managed, unmanaged, or abstract scenarios
  • ABAP behaviour implementation classes (local classes and global handler classes)
  • Service definition and service binding artefacts
  • Unit test class skeletons (ABAP Unit)
Q2Who should use it?
  • ABAP Developers building RAP-based extensions for S/4HANA Public Cloud
  • Technical Leads reviewing generated code before it is transported to the Quality system
Q3What inputs do I need to provide?
  • TDD from Agent 05 — paste or upload the Technical Design Document
  • Database table / CDS view names to be used as the data source
  • RAP scenario type — Managed, Unmanaged, Managed with Additional Save, or Abstract
  • Required operations — Read, Create, Update, Delete, Actions, Validations, Determinations
  • Namespace / naming prefix agreed for the project (e.g., ZAC_, YPRJ_)
  • Draft handling requirement — yes/no flag
Q4What outputs will I get?
  • ZIP archive containing all generated ABAP source files — ready to import via ABAP Development Tools (ADT) in Eclipse
  • A README inside the ZIP explaining the file structure and import sequence
  • Inline code comments explaining key logic decisions
  • A code quality checklist — the agent self-reviews the generated code against SAP RAP best practices and highlights any areas requiring manual review
Q5How do I access it?

In GrowActivAIte, go to Realize → RCEFW Builder → RAP Code Generation. Upload the TDD, complete the form fields, and click Generate Code. Download the ZIP when generation completes. Import the artefacts into your S/4HANA development system using ABAP Development Tools (Eclipse).

Q6What are the prerequisites?
  • Completed TDD from the Technical Design agent (Agent 05)
  • ABAP Development Tools (ADT) installed and configured for your development system
  • Developer user with sufficient authorisations in the S/4HANA development client
  • GrowActivAIte login with the Technical Developer role
  • Agreed naming convention and namespace documented in the TDD
Q7What should I do if something doesn't work as expected?
  • Generated code has syntax errors after import: Review the code quality checklist included in the ZIP — flagged items often indicate where manual adjustment is needed. Check that table/view names entered match exactly (case-sensitive in some contexts).
  • Naming convention not respected: Double-check the namespace prefix field — ensure you did not include a trailing underscore if the template already adds one.
  • Draft handling code is missing: Confirm the Draft handling flag was set to Yes before generating.
  • Log persistent code issues via the in-app Feedback button with the generated code attached.

Agent 07
RCEFW Builder – CAP Code Generation
Realize SAP CAP / BTP RCEFW Builder
Q1What does this agent do?

The RCEFW Builder – CAP Code Generation agent generates SAP Cloud Application Programming (CAP) model code for BTP (Business Technology Platform)-based extensions and side-by-side applications. CAP is the recommended approach for building new cloud-native services that integrate with S/4HANA via APIs. The agent generates:

  • CDS schema definitions (.cds files) for the data model
  • Service definition files exposing OData V4 APIs
  • Node.js or Java service implementation handlers
  • Database configuration files for SAP HANA Cloud or SQLite (development)
  • mta.yaml multi-target application descriptor for BTP deployment
  • Integration event handler code for consuming S/4HANA APIs via SAP Event Mesh or OData
Q2Who should use it?
  • BTP Developers (Node.js / Java) building side-by-side extensions
  • Full-stack developers combining CAP backend with Fiori frontend (use alongside Agent 08)
  • Integration Architects defining the BTP service layer for S/4HANA integration
Q3What inputs do I need to provide?
  • TDD from Agent 05
  • Implementation language: Node.js or Java
  • Database target: SAP HANA Cloud (production) or SQLite (development/test)
  • S/4HANA APIs to be consumed — list of SAP Business Accelerator Hub API names (e.g., API_SALES_ORDER_SRV)
  • BTP subaccount and space names for the mta.yaml
  • Authentication method: XSUAA or IAS
  • Event Mesh requirement: yes/no flag and event topic names if applicable
Q4What outputs will I get?
  • ZIP archive of the full CAP project folder structure ready for development in SAP Business Application Studio or VS Code
  • Pre-configured package.json / pom.xml with required CAP dependencies
  • mta.yaml deployment descriptor
  • Sample OData request collection (Postman/Bruno format) for API testing
  • Deployment guide (Markdown) — step-by-step BTP CF deployment instructions
Q5How do I access it?

In GrowActivAIte, navigate to Realize → RCEFW Builder → CAP Code Generation. Upload the TDD, complete the form, and click Generate Project. Download the ZIP and open in SAP Business Application Studio or your local VS Code with the CDS plugin installed.

Q6What are the prerequisites?
  • Completed TDD from Agent 05
  • SAP Business Application Studio subscription or VS Code with SAP CDS Language Support extension
  • SAP BTP subaccount with Cloud Foundry environment enabled
  • HANA Cloud instance provisioned (for production development)
  • S/4HANA API credentials and destination configuration in BTP
  • GrowActivAIte login with the Technical Developer role
Q7What should I do if something doesn't work as expected?
  • Generated CDS model has entity conflicts: Check that entity names in the TDD do not clash with existing CDS views in your project namespace.
  • mta.yaml has wrong CF org/space: Update the mta.yaml directly after download — the agent populates from your input; verify spelling matches your BTP cockpit exactly.
  • S/4HANA API name not recognised: Verify the API name against the SAP Business Accelerator Hub (api.sap.com). Use the exact service name, not the display name.
  • Report code issues via the in-app Feedback button.

Agent 08
RCEFW Builder – UI Code Generation
Realize Fiori / UI5 RCEFW Builder
Q1What does this agent do?

The RCEFW Builder – UI Code Generation agent generates SAP Fiori / UI5 frontend code for custom applications and extensions. It produces production-grade UI5 application scaffolding, view definitions, controllers, and routing configuration, aligned with Fiori Design Guidelines. Supported patterns include:

  • List Report + Object Page (Fiori Elements)
  • Worklist application
  • Custom Fiori Elements extension (extending a standard Fiori app)
  • Freestyle SAPUI5 application
  • Fiori Launchpad plugin (for custom shell plugin scenarios)
Q2Who should use it?
  • UI5 / Fiori Developers building custom frontend applications
  • Full-stack BTP developers combining this agent's output with CAP backend (Agent 07)
  • UX Leads reviewing application structure and Fiori compliance before development starts
Q3What inputs do I need to provide?
  • TDD from Agent 05 (or a functional UX specification)
  • UI pattern — List Report, Worklist, Freestyle, Extension, or Plugin
  • OData service / CAP service endpoint the UI will consume
  • Key entity sets and properties to be displayed
  • Fiori Launchpad tile configuration — semantic object, action, and parameters
  • Deployment target — SAP S/4HANA Public Cloud embedded FLP, or BTP Launchpad Service
  • UI5 version (latest stable recommended; specify if project requires a pinned version)
Q4What outputs will I get?
  • ZIP archive of the full UI5 application — webapp/ folder structure with manifest, views, controllers, models, i18n files
  • Pre-configured ui5.yaml build and deployment descriptor
  • Fiori Launchpad tile configuration snippet (JSON)
  • Basic Karma/OPA5 test skeleton
  • Fiori compliance checklist — flags any deviation from SAP Fiori Design Guidelines
Q5How do I access it?

In GrowActivAIte, navigate to Realize → RCEFW Builder → UI Code Generation. Upload the TDD or enter the UX specification, complete the form, and click Generate UI App. Download the ZIP and import into SAP Business Application Studio using the Fiori project import wizard, or open directly in VS Code with the SAP Fiori Tools extension.

Q6What are the prerequisites?
  • OData service or CAP service endpoint available and accessible for metadata inspection
  • SAP Business Application Studio or VS Code with SAP Fiori Tools extension pack
  • Fiori Launchpad configuration access (for deployment)
  • GrowActivAIte login with the Technical Developer role
Q7What should I do if something doesn't work as expected?
  • Manifest.json has wrong service URL: Update the dataSources section of manifest.json after download with the correct service URL from your system.
  • Fiori Launchpad tile not appearing after deployment: Verify the semantic object and action in the tile configuration match the PFCG role assigned to your test user.
  • UI5 version conflict: Specify the exact UI5 version used in your system's bootstrap in the agent's UI5 version field before generating.

Realize SAP Forms

The Form Wizard agent guides users through creating and configuring SAP output forms (such as invoices, purchase orders, delivery notes, and payment advice) for S/4HANA Public Cloud. It uses an AI-guided wizard to collect form requirements, then generates the form template configuration and, where applicable, the Adobe Forms or Smart Forms artefact structure. The wizard covers:

  • Field mapping between SAP data structures and form output fields
  • Layout and branding guidance (logos, fonts, colour zones)

  • PDF output configuration for SAP Document Management
Q2Who should use it?
  • Functional Consultants configuring output forms without deep ABAP expertise
  • Technical Consultants who need to create Adobe Forms or Smart Forms artefacts
  • Project teams where the client has specific branding requirements for printed or emailed outputs

  • SAP application component generating the form (e.g., SD Billing, MM Purchasing)
  • Required output fields — list of data fields to appear on the form
  • Client branding assets — logo file (PNG/SVG), brand colours (hex codes), font preferences
  • Languages required — ISO language codes (e.g., EN, DE, FR)
  • Output channels — Print, Email (PDF attachment), Archiving

Agent 10
Interface Mapper
Realize Integration
Q1What does this agent do?

The Interface Mapper agent maps interfaces between SAP S/4HANA and third-party or legacy systems, generating comprehensive interface documentation and field mapping specifications. It automates the time-consuming process of creating interface design documents by:

  • Analysing source and target system schemas to propose field-level mappings
  • Generating transformation logic descriptions for field type conversions, code translations, and data enrichment
  • Producing interface design documents compliant with the SAP Integration Solution Advisory Methodology (ISA-M)
  • Generating integration flow pseudocode or iFlow configuration hints for SAP Integration Suite
Q2Who should use it?
  • Integration Architects designing the interface landscape
  • Integration Developers building iFlows in SAP Integration Suite
  • Functional Leads needing to document interface requirements for client review
Q3What inputs do I need to provide?
  • Source system details — system name, type (SAP, non-SAP, legacy), message format (IDoc, BAPI, REST, SOAP, flat file, EDI)
  • Target system details — same as above
  • Source schema or field list — upload an XSD, WSDL, OpenAPI spec, or paste field names with data types
  • Target schema or field list — same as above
  • Business context description — what data is being exchanged and why (2–5 sentences)
  • Integration middleware — SAP Integration Suite, SAP Process Orchestration, or third-party (Boomi, MuleSoft, etc.)
  • Mapping rules (if known) — any existing mapping logic in free text or a legacy mapping document
Q4What outputs will I get?
  • Interface Design Document (IDD) in Word format
  • Field mapping specification in Excel — source field, target field, transformation rule, mandatory flag, and notes columns
  • Integration flow design summary (pseudocode / configuration notes) for SAP Integration Suite
  • Interface register entry (Excel row) for the project's interface tracker
  • Suggested SAP pre-built integration content (SAP Integration Content Catalogue package names) if applicable
Q5How do I access it?

In GrowActivAIte, navigate to Realize → Interface Mapper. Upload or paste your source and target schemas, complete the business context form, and click Generate Interface Documentation. Review the proposed field mappings in the interactive mapping table (you can adjust individual rows before downloading the final output).

Q6What are the prerequisites?
  • Source and target system schemas or field lists available (even a partial list enables generation)
  • Interface requirements documented (at minimum a 1-paragraph description of what data flows and when)
  • GrowActivAIte login with the Integration Consultant or Technical Lead role
Q7What should I do if something doesn't work as expected?
  • Schema upload fails: Ensure your XSD/WSDL is well-formed XML. Use an online XML validator before uploading. Maximum file size is 5 MB.
  • Mapping suggestions are incorrect: Use the interactive mapping table to override individual field assignments. Click Re-generate after corrections to update the IDD.
  • Integration Suite iFlow notes are missing: Confirm you selected SAP Integration Suite as the middleware. Selecting a third-party middleware suppresses SAP-specific content.

Agent 11
S/4HANA Public Cloud Data Migration Agent
Realize Data Migration
Q1What does this agent do?

The S/4HANA Public Cloud Data Migration Agent assists with all stages of data migration planning and execution for an S/4HANA Public Cloud go-live. It covers:

  • Migration Cockpit ready to load file generation: Produces Transformed data filled SAP migration object file which is ready to be uploaded using Migration Cockpit.
  • Source-to-Target field mapping: Maps source system fields to Target SAP S/4HANA Migration Cockpit object fields.
  • Data Transformation rules: Users can use Business specific Data Transformation rules to override the mapping rules generated by Agent using simple business language prompting.
Q2Who should use it?
  • Data Migration Leads responsible for the migration strategy and execution
  • Functional Consultants (by workstream) validating migration templates for their data objects
  • Technical Migration Developers building extraction, transformation, and load (ETL) scripts
Q3What inputs do I need to provide?
  • Migration objects list — SAP Migration Cockpit object names (e.g., Business Partner, Material, Open AR Items) or a description of what data must be migrated
  • File with Source Data filled — Upload a Source file (Extract from Legacy source system) in CSV/Excel format
  • Migration Cockpit Template for Data object — This is required to make the Agent understand the Target Structure (Field Length, Data Type, Number of worksheets) which Agent needs to generate after Transforming the Source data.
  • Migration Workbook (Optional) — If there is any previously generated Excel Workbook that can help in new Analysis for same Data Object, that can be also uploaded.
Q4What outputs will I get?
  • SAP Migration Cockpit-compatible migration templates (XML/XLSX) pre-populated with Transformed Data along with field mappings
  • Source-to-target field mapping specification (Excel)
  • Data mapping and Transformation rules document (Word) — validation rules with pass/fail criteria for each object
  • Audit Log on the Success or failure of the records
  • .bas file with Macro Script (Works on Chrome)
Q5What should I do if something is not working as expected?
  • Output Migration File fields don't match LTMC: Confirm if the Latest version of Migration Cockpit template was uploaded under the target Section.
  • Field mapping is largely incorrect: Provide a more structured source data file. A well-structured source data file with proper column headers and sufficient sample rows (~10) significantly improves mapping accuracy.

Agent 12
Defect Resolver – Quality Engineering
Realize Quality Engineering Testing
Q1What does this agent do?

The Defect Resolver – Quality Engineering agent is an AI-powered defect analysis tool used during the testing phase (System Integration Testing, User Acceptance Testing). When a tester raises a defect, the agent analyses the defect description, error logs, and test context to:

  • Classify the defect by type (configuration, development, data, environment, test script)
  • Identify the probable root cause based on the error message pattern and process context
  • Suggest resolution steps specific to the SAP S/4HANA Public Cloud context
  • Recommend which team (Basis, Functional, Development, Data) should own the fix
  • Draft a defect resolution note ready to be pasted into the defect management tool (e.g., Cloud ALM, JIRA, ServiceNow)
Q2Who should use it?
  • Testers and QE Engineers raising defects during SIT/UAT
  • Functional Consultants triaging defects assigned to their workstream
  • Test Managers reviewing defect analysis quality and resolution progress
  • Developers receiving defect assignments who need rapid context and suggested fixes
Q3What inputs do I need to provide?
  • Defect title and description — as recorded in the defect management tool
  • Error message or dump — paste the full SAP error message, short dump text, or application log entry
  • Test scenario and test step where the defect was observed
  • SAP module and process area (e.g., FI-AP Invoice Processing)
  • Test data used — relevant master data or transaction data IDs (anonymise if needed)
  • Screenshot or screen recording (optional — upload for visual context)
  • System details: client, release, transport request numbers (if relevant)
Q4What outputs will I get?
  • Defect classification: Type, severity assessment (Critical/High/Medium/Low), and probable owner team
  • Root cause analysis: Likely cause with confidence level (High/Medium/Low) and reasoning
  • Resolution steps: Step-by-step fix instructions (configuration change, code fix, data correction, or workaround)
  • Defect resolution note: Pre-formatted text ready to copy into your defect tracking tool
  • Related SAP Notes/KBAs: Relevant SAP support notes (from SAP's published knowledge base) if the error pattern matches a known issue
Q5How do I access it?

In GrowActivAIte, navigate to Realize → Defect Resolver (QE). Paste the defect details and error information into the input form, attach any screenshots, and click Analyse Defect. The analysis appears within 15–30 seconds. Copy the resolution note directly to your defect management tool.

Q6What are the prerequisites?
  • Active testing phase — the agent is available from the start of SIT preparation
  • GrowActivAIte login with any project role (all team members can use the Defect Resolver during testing)
  • A defect management tool (Cloud ALM, JIRA, ServiceNow) configured for the project — the agent generates the resolution note but does not auto-update the tool
Q7What should I do if something doesn't work as expected?
  • Root cause analysis is incorrect: Provide more context — include the full SAP error message (including the message class and number, e.g., MESG FI001), the transport request, and recent configuration changes in that area.
  • Resolution steps don't apply to S/4HANA Public Cloud (cloud vs. on-premise mismatch): Confirm the SAP System Type is set to S/4HANA Public Cloud in the agent's context selector — some error patterns occur in both environments with different resolutions.
  • No SAP Notes suggested: This is expected for custom development defects. The SAP Notes feature only applies to standard SAP component errors.
  • If the agent's resolution is consistently off for a specific error type, report this via the Feedback button — it helps improve the model for that error class.

Agent 13
Defect Resolver – Run Support
Run Production Support Hypercare
Q1What does this agent do?

The Defect Resolver – Run Support agent provides AI-powered incident analysis and resolution guidance for production and hypercare support issues after go-live. Unlike the QE variant (Agent 12), this agent is tuned for:

  • Higher urgency scenarios — production outages and business-critical process failures
  • Production data context — guides analysts to investigate production symptoms without exposing sensitive data to the AI (the analyst describes the symptom; the agent provides investigation guidance)
  • SAP support escalation guidance — when to open a Priority 1/2 ticket with SAP, what to include, and how to speed up SAP's response
  • Workaround identification — faster path to a temporary workaround to restore business operations while a permanent fix is developed
  • Root cause and permanent fix guidance — same capability as the QE variant, plus change management and transport guidance for production fixes
Q2Who should use it?
  • Application Managed Services (AMS) / Run Support team members handling production incidents
  • Hypercare support consultants during the weeks immediately following go-live
  • Run Support Leads and Service Delivery Managers triaging and prioritising incidents
  • Functional and Technical consultants on hypercare rotation
Q3What inputs do I need to provide?
  • Incident title and description — from the incident management tool (ServiceNow, Cloud ALM)
  • Incident priority — P1 (Critical), P2 (High), P3 (Medium), P4 (Low)
  • Error message or symptom description — SAP error text, dump, or user's description of what they see
  • Affected process and transaction (e.g., "FI Automatic Payment Run — F110 fails with RFFO error")
  • Number of users affected and business impact statement
  • Recent changes — any transports deployed, configuration changes, or SAP updates applied in the past 7 days
  • Steps already tried (optional) — to avoid the agent suggesting steps already ruled out
Q4What outputs will I get?
  • Incident classification and priority validation — confirms or suggests a priority adjustment based on the business impact described
  • Immediate workaround steps — actions to restore business operations as quickly as possible
  • Root cause investigation guide — ordered list of diagnostic steps for the support analyst to follow
  • Permanent fix recommendation — configuration change, code fix, or data correction with transport guidance
  • SAP support ticket draft — pre-filled SAP message template (Component, Short Text, Long Text, Steps to Reproduce) for escalation if needed
  • Incident resolution note — formatted text for the incident ticket's resolution field
Q5How do I access it?

In GrowActivAIte, navigate to the Run phase tab and select Defect Resolver – Run Support. The agent is accessible 24 hours a day, 7 days a week during the contracted support period. Paste the incident details and click Analyse Incident. For P1 incidents, the agent displays a High Priority Mode banner and prioritises workaround steps before root cause analysis.

Q6What are the prerequisites?
  • Go-live completed and the Run phase activated in the project's GrowActivAIte workspace
  • GrowActivAIte login with the Run Support role (assigned by the Service Delivery Manager post go-live)
  • Incident management tool (ServiceNow or Cloud ALM) configured — the agent generates resolution notes but does not auto-update the ticketing tool
  • For P1 incidents: ensure your SAP S-User (support portal user) is available for SAP ticket escalation if needed
Q7What should I do if something doesn't work as expected?
  • Workaround steps don't apply to Public Cloud (on-premise steps suggested): Verify the System Type is set to S/4HANA Public Cloud. Some error messages occur in both environments with different resolution paths.
  • Agent is unavailable during a P1 incident: Contact the GrowActivAIte emergency support line (number provided during onboarding) and use your team's manual incident triage runbook as a fallback. The platform has a target 99.5% uptime SLA.
  • SAP support ticket draft is missing component code: You can find the correct SAP component code in the SAP Component Hierarchy (accessible via the SAP Support Portal) or by asking your Basis Lead. Enter it manually in the generated draft.
  • Analysis consistently misclassifies incidents in a specific area: Report this via the Feedback button with two or three examples. The model is retrained on a monthly cadence using validated feedback.
